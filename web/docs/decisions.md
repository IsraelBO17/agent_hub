# Decisions

Every assumption, deviation from the design and judgment call (standard §6.1). Append only; never rewrite an entry.

| Date | Screen or feature | Decision | Reason | Alternative rejected |
|---|---|---|---|---|
| 2026-10-03 | Setup (#4) | The template's `notes` golden path was removed before the first screen was built, not after (recipe 1, step 9). | `notes` type-checks only against the template's example contract; with `../api/openapi.yaml` it breaks `make check`. Patterns are copied from the `web-standard` repository instead. | Keeping the example contract until the first screen works (two contracts at once). |
| 2026-10-03 | Setup (#4) | Sonner removed with `notes`; no toast library until the first issue that needs a toast adds the Base UI `toast` (profile: Exceptions). | #4 has no mutations, so nothing toasts yet; one library per concern (standard §3). | Adding the Base UI toast now, unused. |
| 2026-10-03 | Setup (#4) | Playwright runs at 1440 × 1024, 768 × 1024 and 390 × 844. | The profile's widths are the design's frames plus a tablet. | The template's 1280 and Pixel 7 (412). |
| 2026-10-03 | Setup (#4) | `/` shows a placeholder "All agents" page until the shell and the catalog are built. | The index route needs a screen once `notes` is gone. | Keeping a `notes` route as the index. |
| 2026-10-03 | Shell (#4) | Until #6, #7 and #8 load them, the Agent Switcher, the session list, the user and the Chat Header's agent show their loading skeletons. | They are the designed loading state those issues start from, and they keep the layout's final size. | Hiding them (the shell would jump when data arrives) or mock data (catalog data is #7). |
| 2026-10-03 | Shell (#4) | Search is shown disabled with "Soon"; the keyboard hints (⌘⇧O, ⌘K) are left out. | The ⌘K palette is P1 and the shortcuts don't exist yet; a hint for a missing shortcut misleads. | Hiding Search (the design shows it). |
| 2026-10-03 | Shell (#4) | No hover or pressed styles on buttons and nav items. | They aren't drawn (UI_COMPONENTS §5 item 2): settled in Pencil first. | Inventing them in code. |
| 2026-10-03 | Shell (#4) | On mobile, HubLayout's App Header shows the menu and the brand; the design's Top Bar shows the page title and Search. | The page's h1 is in the content; Search is P1. | A page-specific top bar per screen. |
| 2026-10-03 | Shell (#4) | The drawer is never wider than the screen less 48 px, and a collapsed desktop sidebar is inert. | At 360 px a 316 px drawer leaves 44 px of scrim to tap; off-canvas links must not take keyboard focus. | shadcn's 3/4-width sheet. |
| 2026-10-03 | Tokens (#4) | Shadows and layout sizes are read from the Pencil components that `design/scale.json` names; only numbers (type scale, radii) are kept in that file. | No value is copied from the design by hand, and a design change reaches `make tokens`. | Copying the shadow values into scale.json. |
| 2026-10-03 | Tokens (#4) | shadcn's radius and shadow names (`rounded-md`, `shadow-sm`, …) are aliases onto the design's scales in `theme.css`. | Vendored primitives keep working until each is restyled; only design values exist. | Leaving Tailwind's default scales in place. |
| 2026-10-03 | Fonts (#4) | Inter and JetBrains Mono are self-hosted with `@fontsource-variable/inter` and `@fontsource-variable/jetbrains-mono` (family names "Inter Variable", "JetBrains Mono Variable", mapped in scale.json). Roboto (Google button) comes with #6. | Standard §18: self-hosted fonts. | Google Fonts at runtime (CSP, privacy). |
| 2026-10-03 | Primitives (#4) | Every primitive in `web/` is restyled to its Pencil component now: Button, Tooltip, Sidebar, Sheet backdrop, Card (Content Card), Dialog, Confirm Dialog, Form Field (Field, Label, Input, Textarea), plus Empty State and the page heading. Primitives not yet in `web/` are added and restyled by the issue that first uses them (owner, option 3). | Nothing in `web/` keeps shadcn's default look. | Adding all ~23 missing primitives now, before their hover, pressed and disabled states are drawn. |
| 2026-10-03 | Primitives (#4) | Disabled controls dim to 50 %, and an invalid control's border turns `danger`; neither is drawn yet. | Disabled and invalid must be visible (standard §15, §16); replace with the drawn states when UI_COMPONENTS §5 item 2 is settled. | No visible disabled or invalid state. |
| 2026-10-03 | Sign-in (#6) | Signed in for real, the button is Google's own (Google Identity Services `renderButton`: outline, "Continue with Google", rectangular, up to 400 px), not the drawn Pencil Google Button. | Only Google's button or One Tap gives the browser an ID token; a drawn button would need a hidden overlay or a token in the URL (standard §14). The two look nearly the same; "Signing in…" is ours. (Owner, 2026-10-03.) | A custom button over a hidden Google one. |
| 2026-10-03 | Sign-in (#6) | In mock mode a button drawn like the Pencil Google Button sends a fake credential (`mock-google-id-token:<email>`) that only the MSW handler accepts. | Google can't run offline, in CI or in e2e. (Owner, 2026-10-03.) | Loading Google in tests. |
| 2026-10-03 | Sign-in (#6) | `account_disabled` reuses the not-allowed layout, with its own title and text. | Not drawn. (Owner, 2026-10-03.) | A generic error line. |
| 2026-10-03 | Session (#6) | When a refresh fails mid-session, the user goes to `/sign-in?next=…`; the in-place "Session expired" dialog that keeps a draft (`N8ysh`) comes with the composer in #8. | There is no draft to keep before #8. (Owner, 2026-10-03.) | Building the dialog now. |
| 2026-10-03 | Session (#6) | Sign out lives in Settings → Account, as drawn (`RHrDH`); the rest of Settings stays a placeholder. | The design puts it there. (Owner, 2026-10-03.) | A user menu on the avatar (not drawn). |
| 2026-10-03 | Session (#6) | Avatars show initials only, never the Google photo. | The CSP allows images from `self` only; a photo would need Google's image host in `img-src`. | Adding `lh3.googleusercontent.com` to the CSP. |
| 2026-10-03 | Session (#6) | Ending the session sets the session query to "signed out" and removes every other query, rather than clearing the whole cache. | Clearing the cache detached the screens watching the session, so a sign-out in another tab didn't reach them (found by the test). | `queryClient.clear()`. |
| 2026-10-03 | Catalog (#7) | "Continue where you left off" is left out until `GET /v1/sessions` exists (M2). | Built on mocks only, it would show an error against the real API. (Owner, 2026-10-03.) | A mock-only section. |
| 2026-10-03 | Catalog (#7) | "Register an agent" and "How to register an agent" link to `docs/AGENT_PROFILE.md`; on mobile the header link is hidden, as drawn. | Registering in the app is P2. (Owner, 2026-10-03.) | Hiding them. |
| 2026-10-03 | Catalog (#7) | An offline agent's card dims only its avatar, not the whole card (the design: 72 % opacity). | At 72 % its text fails WCAG contrast (axe). | Dimming the card. |
| 2026-10-03 | Agents (#7) | Agent icons are any lucide name from the descriptor, drawn with lucide's `DynamicIcon`, loaded lazily (its name map is about 15 KB); unknown names show `bot`. | Agents are data: the app can't list their icons. | A fixed icon list in the app. |
| 2026-10-03 | Switcher (#7) | The switcher's menu and sheet (Base UI Menu, Drawer) load the first time it opens, prefetched on hover or focus. | With them in the first load, initial JS was 214 KB (budget 200); now 191 KB. | Raising the budget. |
| 2026-10-03 | Switcher (#7) | The switcher's "Switch agent…" search field waits for P1. | With one agent it adds nothing. (Owner, 2026-10-03.) | Building it now. |
