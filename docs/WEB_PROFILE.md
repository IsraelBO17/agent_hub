# Web profile: Agent Hub (project `fleet`)

Agent Hub's web app follows the [Web Development Standard](https://github.com/IsraelBO17/web-standard/blob/main/docs/STANDARD.md) (1.1) and is built from the [`web-standard`](https://github.com/IsraelBO17/web-standard) template, whose contents live in `web/` (D24). This profile adds Agent Hub's values and the choices the standard leaves to a profile (standard §26). It never weakens the standard. Where a rule here and a decision in [`ARCHITECTURE.md`](ARCHITECTURE.md) disagree, the decision wins and this file is fixed.

## Rules

| Topic | Agent Hub rule |
|---|---|
| Repository | Monorepo (D24): the template's files go in `web/` (npm, its own `package-lock.json`, `web/CLAUDE.md`, `web/Makefile`); the root `Makefile` calls them as `make web-*`. CI is `.github/workflows/web.yml`, running the template's gate in `web/` on changes to `web/**`, `api/openapi.yaml` or the workflow |
| Exceptions | Toasts use the **Base UI `toast`** component, not Sonner (D28). Mobile sheets that slide up use the Base UI `drawer` (D28). **Deleting a session uses undo, not a confirmation** (owner, 2026-10-03; standard §8.5 says confirm): it disappears at once with a 10-second Undo toast (F06, F7.6–F7.7), because the API keeps it restorable for that window (`api/openapi.yaml`, `sessions.deleted_at`). Everything irreversible confirms first. No other exceptions |
| No Radix | Nothing from `@radix-ui/*`, directly or through a dependency (D28): no shadcn `command` (the ⌘K palette is Base UI Autocomplete in the shadcn Dialog). `make check` adds `npm ls --all` and fails if `@radix-ui` appears |
| Design source | [`design/fleet_dev.pen`](../design/fleet_dev.pen), a Pencil file that is plain JSON. Rules for editing it are in the root `CLAUDE.md` (save, `python3 design/tools/pen_index.py`, commit both). The design wins over shadcn's defaults (D28) |
| Token pipeline | `scripts/tokens/read-design.ts` in `web/` is replaced by a Pencil adapter: **colours and fonts** come from the file's `variables` (88 colours; `font-ui` Inter, `font-mono` JetBrains Mono, `font-google` Roboto for the Google button only). The file has no variables for sizes, so `web/design/scale.json` holds the **type scale and radii** (numbers only) and names the Pencil component each **shadow** and **layout size** is read from (`K1CWuA` for `shadow-control`, `hj5RV` for the sidebar width, …; values in [`UI_COMPONENTS.md`](UI_COMPONENTS.md) §1). Both feed `make tokens`, which writes `tokens.css` and `src/lib/token-names.ts`; neither is edited by hand. Hex values are only ever in the design file. Fonts are self-hosted (`@fontsource-variable/inter`, `@fontsource-variable/jetbrains-mono`); scale.json maps each design font to its hosted family name |
| Type scale | 12, 13, 14, 15, 20, 28, 40 px and nothing else (Tailwind's defaults removed), named by size: `text-12` … `text-40`. Default line heights: 12 → 16, 13 → 18, 14 → 20, 15 → 22, 20 → 26, 28 → 34, 40 → 46 px; a component overrides only with a leading token. `web/src/lib/utils.ts` builds `cn` with `createCn` from `cn/config`, told these names (and the radius and shadow names) from the generated `token-names.ts`, because plain `cn` drops `text-13` next to a text colour. Vendored primitives import `cn` from `@/lib/utils`. `make check` fails on any other font-size class, vendored files included |
| Radii, shadows | Radii `rounded-4`, `5`, `6`, `7`, `8`, `9`, `10`, `12`, `14`, `16`, `full`; shadows `shadow-control`, `raised`, `float`, `popover`, `dialog`, `palette` (values in UI_COMPONENTS §1). Tailwind's own radius and shadow scales are removed; shadcn's names (`rounded-md`, `shadow-sm`, …) are aliases in `theme.css` until each primitive is restyled |
| Colour rules | Agent colours (`agent-*-bg/fg`) only for agent identity (avatar tiles), never as decoration. Callouts, badges and favicons use `info` / `highlight` and the status sets. Overlays use `scrim`, `scrim-light`, `scrim-strong`. Light theme only: no dark tokens exist (PRODUCT_PLAN §9 item 12) |
| shadcn mapping | As in UI_COMPONENTS §1. **Name clash:** Pencil's `accent` is the brand green and maps to shadcn's `--primary`; shadcn's `--accent` (a menu item's hover fill) maps to Pencil's `hover`. The design's `accent`, `border` and `sidebar` colours keep their meaning as Tailwind colours (`bg-accent` is green); primitives write `bg-hover` where shadcn writes `bg-accent`. `--ring` is `focus-ring`: every focusable control shows a 2 px outline with a 2 px offset (the Focus Ring component and the "States · Focus" board); menu, palette and list rows use their highlight fill instead |
| Components | Pencil → shadcn map, setup and open design gaps: [`UI_COMPONENTS.md`](UI_COMPONENTS.md). Generated primitives in `web/src/components/ui/`, restyled in place to their Pencil component (each file notes it: `// Design: <component> (<id>)`); Agent Hub's domain-free composites in `web/src/components/application/` (D28), which lint treats like the rest of `components/`. Add a primitive in the issue that first needs it. A hover, pressed or disabled state the file doesn't draw is settled in Pencil first, not invented in code |
| Destructive actions | Session delete: immediate, with the Undo toast (see Exceptions; product principle 4). Irreversible actions (Delete all, F9.2) use `ConfirmDialog`, restyled to the Pencil Confirm Dialog `i3B1e`, with a typed `DELETE` field |
| Icons | lucide (`lucide-react`) through `components/ui/icon`. The Pencil file lacks `clock` and `fingerprint`; lucide-react has both, so code may use them where the design substituted `timer` or `shield-check` only if the design is updated to match |
| Layout | Desktop frames 1440 × 1024: sidebar **284 px** (`--layout-sidebar-width`), app header, chat column about **760 px** (`--layout-chat-width`), artifact panel about 50 / 50 with the chat (resizable). Mobile frames 390 × 844: the sidebar becomes the sessions drawer (F10.5); the artifact panel becomes a full-screen sheet |
| Widths | Screenshot and check at **390, 768 and 1440** (the design's widths), and confirm nothing breaks at 360 |
| Touch | 44 px tap targets on coarse pointers by enlarging the hit area, not the drawn size (UI_COMPONENTS §5.6) |
| Content types | A closed set of message blocks, one renderer each, from the contract's `MessageBlock`: `text`, `thinking`, `tool`, `plan`, `artifact`, `file`, `question`, `answer`, `approval`, `citations`, `chart`, `image`, `form`. Artifacts are `document`, `code`, `html` or `table` (F09). An unknown block type renders a neutral "Unsupported content" row, never a crash. New agents reuse these renderers; there is no agent-specific UI (product principle 5) |
| Untrusted content | Agent text is GitHub-flavoured Markdown through `SafeMarkdown` (no raw HTML; GitHub alert syntax becomes Callouts without `role="alert"`). `html` artifacts render only in an `<iframe sandbox="allow-scripts">` (never `allow-same-origin`) served from a separate origin with its own CSP and no network by default (F09; the origin is decided in the artifacts issue). Charts follow [`CHART_SPEC.md`](CHART_SPEC.md) through `<ChartBlock>` (Recharts, lazy-loaded); no shadcn `chart` |
| Contract | [`api/openapi.yaml`](../api/openapi.yaml) (D23). `make api` in `web/` reads `../api/openapi.yaml`; `make check` fails on drift. Errors are RFC 9457 problems with `code`, `requestId`, `retryable`, `retryAfter`; field errors use the `invalid_request` code with status **422** (API_PROFILE); the standard's `toApiError` reads them unchanged. `requestId` is shown as "Reference: req_…" in error states |
| Identity | Google sign-in (D8): Google Identity Services in the browser (`VITE_GOOGLE_CLIENT_ID`), the ID token posted once to `POST /v1/auth/google`. Access token about 15 min in memory; refresh token in an `HttpOnly; Secure; SameSite=Strict; Path=/v1/auth` cookie, host-only on `api-fleet.qucoon.com`; requests to the API use `credentials: 'include'`. App and API are different origins on the same site (`qucoon.com`), so the cookie is same-site (D25). `403 not_invited` and `403 account_disabled` have their own screens. No idle timeout in v1. Built in issue #6: Google's own rendered button (Google Identity Services) gives the ID token; in mock mode a stand-in drawn like the Pencil Google Button sends a fake credential to MSW. Avatars show initials (no Google photos: the CSP allows images from `self`). Sign out is in Settings → Account |
| Streams | `POST /v1/sessions/{id}/messages` returns SSE read with `fetch` (D5). Events and statuses: [`SEND_MESSAGE.md`](SEND_MESSAGE.md) and the contract (`run.started`, `block.*`, `artifact.delta`, `run.completed`, `run.awaiting_approval`, `run.stopped`, `run.failed`). API keep-alive `: ping` every 15 s. **Stall: 45 s with no bytes**; then the client stops reading and **polls the message every 2 s while it is `streaming`** (no stream resume in v1). After 60 s with no events (pings don't count) the reply shows a soft "Still working" note, not an error. Stop is `POST /v1/messages/{messageId}/stop` (P4), then the stream is aborted |
| Polling | Sessions list every **20 s** while the tab is visible (D22: working dot, approval badge and toast, "Task complete" toast); an offline agent every **30 s** to unlock the composer; `refetchIntervalInBackground: false` everywhere |
| Mocks | MSW, per the standard, replaces F14's `AgentApi` interface (D29): the mock is the network layer, so the real client and SSE reader run on mock data. The **Scenario Agent's scripts are MSW scenarios** (`?scenario=<name>`: offline, degraded, slow, dropped stream, expired approval, …), and the Playwright scenario suite runs every one of them in CI (F14). `VITE_API_MOCKS=true` in development and CI only; the deployed build never has mocks on. The full scenario set is M2 |
| Budgets | Initial JS 200 KB gzip (the default). Markdown, syntax highlighting, Recharts and the artifact viewers are lazy |
| Locale | The browser's locale and time zone (the standard's `utils/format-date` with both undefined) (owner, 2026-10-03); RFC 3339 UTC on the wire. Money appears only inside agent blocks (a chart's `currency` format), shown through `formatMoney` with the block's currency code |
| Monitoring | `reportError` is wired from the start; **Sentry is switched on at M4**, before v1 (D29). Until then errors go nowhere in production, and that's accepted |
| Hosting | **AWS Amplify Hosting** (D13): the existing app `fleet-dev-web-amplify-us-east-1`, monorepo build spec in `infra/modules/amplify` (app root `web`, `npm ci`, `npm run build`, artifacts `dist`); it selects Node from `web/.nvmrc` with `nvm` before `npm ci`, and stamps `VITE_RELEASE` with the commit. Rewrites: every path that isn't a file → `/index.html` (200). Custom headers in Amplify: the standard's set, with Google Identity Services' sources added: `script-src 'self' https://accounts.google.com/gsi/client`, `frame-src https://accounts.google.com/gsi/` (plus the artifact sandbox origin when it exists), `connect-src 'self' https://api-fleet.qucoon.com https://accounts.google.com/gsi/`, `style-src 'self' 'unsafe-inline' https://accounts.google.com/gsi/style` (inline style *attributes*: Base UI positions popups with them; scripts never run inline). The headers, the build spec and the domain are in `infra/modules/amplify`; the GitHub connection is made once by hand (`infra/README.md`). The rewrite rule already in Terraform serves `index.html` for every path without a file extension. Build env: `VITE_API_URL=https://api-fleet.qucoon.com`, `VITE_GOOGLE_CLIENT_ID` (public, D15) |
| Environments | One environment, `dev`, until v1 (D17), deployed from `main`. Pull requests get Amplify previews only if the owner turns them on (they need the Google OAuth origin and CORS per preview, so they run in mock mode) |
| Domain | `https://fleet.qucoon.com` as a CNAME to Amplify in the `qucoon.com` zone, added by the domain owner from Terraform's `dns_records_for_qucoon` output (D25). Until the CNAME and its validation record exist, the Amplify default domain is used. Share links `https://fleet.qucoon.com/s/<slug>` (P1) |
| Cloud | AWS account `ml_account` (992382810653), us-east-1, shared with other projects (D27). Amplify is managed in `infra/` (Terraform); plan with `AWS_PROFILE=ml_account` and apply only on the owner's yes |
| Names and tags | `fleet-<env>-<component>-<type>-<region>` (D26), e.g. `fleet-dev-web-amplify-us-east-1`. Tags `Owner`, `Project=fleet`, `Environment`, `aws-apn-id`, `ManagedBy=terraform` through provider `default_tags`; `Owner` and `aws-apn-id` values only in the gitignored `infra/envs/dev/terraform.tfvars` (this repository is public) |
| Decision log | Technical decisions in [`ARCHITECTURE.md`](ARCHITECTURE.md) (D-numbers). Screen-level judgment calls and deviations from the design in `web/docs/decisions.md`, as the standard says |

## Building on this profile

1. Work in `web/`, following `web/CLAUDE.md` (from the template) and the recipes in `web/docs/RECIPES.md`.
2. Use these values wherever a recipe says "from the profile"; the design wins on looks, the contract on data, and `ARCHITECTURE.md` on everything else. Anything none of them settles is a question for the owner.
3. A change that would contradict a decision (D1–D29, P1–P8) is proposed in `ARCHITECTURE.md` first. A gap in the standard or template is fixed in `web-standard` with a version bump, not worked around here.

## Gaps found while building `web/` (fixed in `web-standard` 1.1)
- Monorepo setup (CI in the folder, `CONTRACT` in the Makefile, Dependabot, root shortcuts): recipe 1, step 0.
- The token generator: several sources, shadows, the design owning the radius and shadow scales, and the size names `cn` needs.
- `make check` rejects font-size classes outside the type scale; the axe helper skips endless animations.
